# 按昵称搜索账号并抓取其笔记 —— 设计方案 v2

> 状态：**方案已定稿，待实现**
> v1 → v2 的改动：账号模式下关键词改为**前端本地按标题筛选**（不再服务端过滤）；排序支持**最新 / 点赞最高**；账号列表**扫多少展示多少**；候选认人依据确定为**小红书号 + 粉丝数 + 头像**。
> 关联页面：热点创作 → 样本搜索
> 关联模块：`creative_service`、`api/platforms/xhs/creative.py`、`pc_api_adapter`、`hot-content-page.tsx`

## 1. 目标

在现有「关键词搜索」之外，新增**按昵称找账号 → 抓取该账号的笔记 → 人工勾选**的样本来源。

## 2. 已确定的决策（grillme 三波追问的结果）

| # | 问题 | 决策 |
|---|---|---|
| 1 | 账号取样口径 | **最新 / 点赞最高 两种，用户选** |
| 2 | 按点赞排序的边界 | **只扫最近 300 篇**（约 10 页），在这 300 篇里排序，超出范围不保证 |
| 3 | 候选认人依据 | **小红书号 + 粉丝数 + 头像**（不自动选第一个） |
| 4 | 无标题笔记导致的关键词过滤失效 | **不做服务端过滤**；关键词只在已加载列表里**前端按标题筛** |
| 5 | 列表展示范围 | **扫多少展示多少**（最多 300），默认勾选排序后的前 N 篇 |
| 6 | 首次搜索限制 | 关键词与昵称**只能填一个**，双填禁用并提示 |

### 为什么关键词只做前端筛选

账号列表接口（`user_posted`）只返回 `display_title / cover / interact_info / time / xsec_token`，**没有正文和标签**。要在服务端按正文/标签过滤，就必须对每篇笔记额外拉一次详情（1 秒/篇、几十次请求、风控风险高），收益不成立。

因此账号模式的关键词定位为：**对已加载列表做标题包含匹配的本地筛选**，不发新请求、结果即时、范围明确（"在已加载的 N 篇里"）。命中少时文案说明，不假装全量搜索。

## 3. 用户流程与交互规则

### 3.1 输入区

```
┌──────────────────────────────────────────────────┐
│ 来源  (关键词) (账号)                              │
│ 关键词  [____________________]                    │
│ 昵称    [____________________]  [搜索账号]         │
│ 数量    (20) (30) (50)                            │
│ 排序    (最新) (点赞最高)         ← 账号模式才显示  │
└──────────────────────────────────────────────────┘
```

### 3.2 规则表

| 状态 | 关键词 | 昵称 | 按钮 | 行为 |
|---|---|---|---|---|
| A 初始 | 空 | 空 | 禁用 | 提示「请输入关键词或昵称」 |
| B | 有 | 空 | 可用 | 关键词搜索（现有逻辑） |
| C | 空 | 有 | 可用 | 昵称 → 候选列表 |
| D 双填（首次） | 有 | 有 | 禁用 | 「首次搜索只能填其中一个」 |
| E 已选账号 | 任意 | 锁定 | 可用 | 关键词＝**本地标题筛选**，不发请求 |
| F 已选账号 | 空 | 锁定 | 可用 | 展示全部已加载笔记 |

补充：

1. 选中账号后展示来源 chip：「样本来源：PixPix（小红书号 63677579548）」+ 退出按钮；
2. 退出账号模式 → 清空关键词筛选 → 回到状态 A/B；
3. 账号模式下的「数量」只决定**默认勾选多少篇**，不限制列表展示数量；
4. 切换排序（最新/点赞最高）会**重新拉取**（点赞排序需要扫 300 篇后才能定序）。

## 4. 后端设计

### 4.1 数据源（已实测）

| 能力 | 方法 | 验证 |
|---|---|---|
| 昵称 → 候选 | `XHS_Apis.search_user(query)` | ✅ 15 个候选，含 `id/name/image/fans/red_id` |
| 账号 → 笔记 | `XHS_Apis.get_user_note_info(user_id, cursor)` | ✅ 只传 `user_id` 即可，每页 30 条 |
| 归一化 | `_normalize_search_item()` | ✅ 已兼容扁平结构，直接复用 |

### 4.2 接口

#### ① 昵称 → 候选

```
POST /api/xhs/creative/users
{ "account_id": 1, "nickname": "PixPix" }
→ { "users": [ { "user_id": "...", "name": "PixPix", "red_id": "63677579548",
                 "avatar": "https://...", "fans": "1546", "note_count": 22,
                 "description": "软件公司" } ] }
```

- 取前 10 个；`user_id` 优先 `id`，否则从 `link`（`xhsdiscover://1/user/user.<id>`）解析；
- 不建任务；无结果返回 400。

#### ② 账号 → 笔记

```
POST /api/xhs/creative/search-account
{ "account_id": 1, "user_id": "...", "nickname": "PixPix",
  "sort": "latest" | "likes",      // 默认 latest
  "scan": 300,                      // 最多扫描篇数，上限 300
  "limit": 30 }                     // 默认勾选篇数，仅作回传提示
→ 202
{ "id": 57, "task_type": "creative_search", "status": "completed",
  "payload": {
    "search": { "source": "user", "user_id": "...", "nickname": "PixPix",
                "red_id": "...", "sort": "likes", "scan": 300, "scanned": 287 },
    "items": [ ...按 sort 排好序，最多 300 条，结构同关键词搜索... ],
    "default_selected_ids": ["...", "..."],   // 前 limit 条
    "warnings": [] } }
```

- 任务类型仍是 `creative_search`，`payload.search.source = "user"`；
- `items` 与关键词搜索同构 → 采集/勾选/生成/报告**零改动**；
- 点赞排序：扫满 `scan` 或账号到底后，按 `likes` 降序；最新排序：按 `timestamp` 降序（扫到 `scan` 或到底）。

### 4.3 翻页策略

```
cursor, scanned = "", 0
while scanned < scan:
    if cursor: sleep(1)
    notes, cursor, has_more = get_user_note_info(user_id, cursor)
    for note in notes: items.append(normalize(note)); scanned += 1
    if not has_more or not notes: break
items.sort(key=likes_desc if sort=="likes" else timestamp_desc)
```

- 每页 30 条，页间 `sleep(1)`；
- 300 篇 ≈ 10 页 ≈ 10 秒 + 网络；
- 到底不足 300 → warning「该账号共 N 篇公开笔记」；
- 被风控/失败 → 已拿到的保留，warning + 任务 completed（不整体失败），这与关键词搜索的容错一致。

### 4.4 归一化与安全

- 复用 `_normalize_search_item()`，随后 `raw={}`、`note_id` 转字符串去重、`valid_note_url()` 校验；
- `note_url` 带 `xsec_token`，`xsec_source` 用 `pc_user`（主页来源），降低采集 404；
- 私密/仅粉丝可见/已删除笔记不会出现，属预期。

### 4.5 错误与边界

| 情况 | 行为 |
|---|---|
| 昵称无结果 | 400「没有找到该昵称的账号」 |
| 多个候选 | 返回列表，不自动选 |
| 账号无公开笔记 | 200 + `items=[]` + warning |
| 账号全部无标题 | 200 + items 有值但标题为空；前端筛选提示「标题为空的笔记无法被关键词命中」 |
| `user_id` 非法 | 400，不建无用任务 |

## 5. 前端设计

### 5.1 改动点

1. 来源切换（关键词 / 账号）；
2. 昵称输入 + 候选列表（头像、昵称、小红书号、粉丝数、「用这个账号」）；
3. 账号 chip + 退出；
4. 排序选择（账号模式）；
5. 关键词框在账号模式下变为本地筛选（`useMemo` 过滤 `items`），placeholder「在已加载的 N 篇里筛选标题」；
6. 列表默认勾选 `default_selected_ids`；
7. 采集/生成区域复用现有组件。

### 5.2 文案

| 场景 | 文案 |
|---|---|
| 双空 | 请输入关键词或昵称后再搜索 |
| 双填（首次） | 首次搜索只能填关键词或昵称其中之一 |
| 候选为空 | 没有找到该昵称的账号，试试完整昵称或小红书号 |
| 账号模式筛选 | 已在 N 篇里按标题筛选，命中 M 篇（不含无标题笔记） |
| 账号笔记不足 | 该账号共 N 篇公开笔记，已全部加载 |
| 点赞排序范围 | 排序基于最近 300 篇，更早的爆款未纳入 |
