# XHS_ALL_IN_ONE 二次开发项目档案

> 这份文档用于记录本 Fork 的项目理解、产品决策、技术改动、验证结果和可复用的简历素材。
> 每完成一个小任务都要更新：日期、问题背景、实现方式、测试结果、提交号和后续边界。

## 1. 项目概览

### 1.1 原项目定位

`XHS_ALL_IN_ONE` 是一个面向小红书的全链路运营平台，原始定位覆盖：

- 小红书 PC 端与创作者平台账号登录、Cookie 管理和状态巡检。
- 关键词搜索、笔记详情、评论和用户内容采集。
- 内容库、标签、素材下载及 JSON/CSV 导出。
- AI 标题、正文、标签改写以及图片生成、图片润色和图片描述。
- 草稿编辑、发布中心、立即发布和定时发布。
- 自动运营、数据洞察、竞品监控、通知和任务中心。
- 基于 FastAPI 的 Python 后端、React 前端、SQLite/MySQL 配置和 Docker 部署。

原项目的优势是功能覆盖面广、底层小红书适配能力较完整，并且已经具备账号、任务、模型配置和发布等基础设施。它的代价是功能入口很多，采集、AI 创作和自动发布耦合在同一个运营平台中；对于只想“搜索热点 → 分析 → 写文案 → 自己配图”的使用场景，学习成本和操作路径偏长。

### 1.2 原项目技术结构

| 层级 | 原项目实现 | 本项目使用方式 |
|---|---|---|
| 小红书适配 | `apis/`、`xhs_utils/`、`static/` 签名和请求能力 | 不直接改底层 SDK，通过 `backend/app/adapters/xhs/` 调用 |
| 后端 API | FastAPI 路由、Pydantic Schema | 复用认证、账号、模型、任务和文件下载能力 |
| 业务服务 | SQLAlchemy、后台任务、调度器 | 新增热点创作和后续多 Agent 流程 |
| 前端 | React 19、Ant Design、Vite | 收敛为热点创作主流程，保留高级能力 |
| 数据持久化 | SQLite 或 MySQL | 本地试用使用 SQLite，报告和正文保存到本地存储 |
| AI 接口 | OpenAI 兼容 `/chat/completions` | 复用文字模型配置，暂不自动调用生图和发布接口 |

### 1.3 原项目分析与改造边界

原项目不是从零开始的爬虫，而是一个已经包含账号、采集、AI、发布和自动运营能力的综合平台。因此本 Fork 采取“复用基础设施、增加垂直工作流”的方式：

1. 不重复实现登录、Cookie 加密、模型配置、通用任务和文件下载。
2. 不直接修改底层签名 SDK，避免破坏原项目已有平台能力。
3. 优先完成可人工验收的热点创作流程，再实现定时日报和桌面打包。
4. 新流程默认不自动发布、不自动生图，图片由使用者自行生成或寻找有授权的素材。
5. 所有生成内容都需要人工审阅，不承诺一定爆款，也不把搜索样本当作全站趋势。

## 2. 本 Fork 的产品目标

绑定小红书 PC 账号后，用户可以：

1. 输入关键词并选择排序、时间、笔记类型和 20/30/50 篇数量。
2. 勾选需要分析的笔记，批量采集完整正文和互动数据。
3. 将本批样本交给 AI，生成多个选题、标题、可直接发布的正文、标签和配图提示词。
4. 按“标题 → 文案版本 → 配图建议”查看成套内容，复制正文或完整笔记。
5. 导出 HTML/JSON 日报，之后再复用同一流程实现自定义定时任务。

当前阶段不包含：自动发布、自动生图、绕过登录验证、保证流量、从样本图片中推断视觉趋势。

## 5. 当前多 Agent 改造

### 5.1 已确认的阶段拆分

目标流程为：

`样本分析 Agent → 读者需求 Agent → 选题 Agent → 选题评委 → 标题 Agent → 标题评委 → 文案 Agent → 文案评委 → 配图 Agent → 最终评委`

上述阶段尚未接入真实生成流程。沿用此前 M3～M12 实施安排，角色的详细职责见 [Agent 详细职责说明](creative-agent-plan.md)，不另行拆分或重排开发任务。

职责说明采用 6 个生产角色、1 个复用评委角色和程序调度器，列明各角色输入、输出、边界和交接；样本、受众、配图的评审规则仍需实现。按既定方案限制返工，网络超时不属于内容返工，不自动重发；这些接入能力尚未完成。

### 5.2 M0～M2 基础层

本轮新增但尚未接入旧生成流程的基础模块：

- `creative_quality.py`：固定的选题、标题、正文和最终组合评分标准，包含权重、阻断项、总分和通过条件。
- `creative_pipeline.py`：可序列化的阶段状态、尝试记录、当前阶段、阶段输出和评审结果；尚未接入数据库持久化。
- `creative_orchestrator.py`：统一处理结构化 JSON 解析、Pydantic 字段校验、阶段进度回调和内容校验失败返工。
- `test_creative_agents.py`：覆盖评分、阶段状态、JSON 修复、耗尽重试和传输错误不重试。

本轮的设计原则是：先搭建稳定的 Agent 基础层，再逐步替换原来的单次综合分析；基础层完成不会改变当前用户可见的旧流程。

### 5.3 评委标准

标题评委关注：点击吸引力、具体程度、读者收益、关键词和受众匹配、差异化、自然度。

文案评委关注：前两句吸引力、具体信息、目标读者匹配、小红书语气、收藏/转发价值、直接发布可用度。

最终评委关注：标题和正文一致性、正文是否兑现标题、配图是否匹配、标签是否重复、事实和素材边界。

拟定接入规则：任何阻断项不通过时，结果不能直接进入最终成稿展示；评委只能提出返工建议，不能降低代码内置的通过阈值。目前已有评分函数及 M6 选题评委独立调用模块；其他阶段评委、质量返工和真实工作流展示拦截尚待实施。

### 5.5 M3 样本分析 Agent（独立模块）

问题背景：原综合提示词同时承担样本归纳、选题、标题、正文和配图，难以单独核对样本分析是否正确。M3 先拆出可测试的分析模块，不改变用户正在使用的旧流程。

技术实现：

- 新增 `backend/app/schemas/creative_agents.py`：逐篇观察、原文证据、题材/风格/价值模式和分析局限的 Pydantic 模型；未知字段不接受，分析结果不包含发布正文。
- 新增 `backend/app/services/creative_agents/sample_analysis.py`：独立样本分析提示词、白名单输入、来源覆盖/引文校验、程序计算的证据篇数与版本元数据。
- 支持 3～50 篇有效样本，不静默丢弃重复或空正文；对非法输入明确报错。总正文摘录预算 24,000 字符，每篇最多 1,800 字符，保留首尾并记录截断；标题最多 160 字符，额外标题字段也记录截断。
- 缺失或非法互动数据保留为未知，不当作观测到的零；不发送账号 ID、Cookie、API Key、原始响应、作者信息或媒体地址等非必要字段。
- 扩展 `creative_orchestrator.py` 的可选 `validate_output` 回调，使覆盖和来源错误可进入既有最多一次修复流程；补齐畸形 Markdown 代码块的可控失败，并避免将校验输入值/未知字段名抄入错误记录。
- 模型传输入口复用现有模型归属检查、连接 10 秒/读取 180 秒的超时分类；网络、HTTP 或响应解析失败不自动重发。
- 新增 `tests/backend/test_creative_sample_agent.py`，使用模拟响应和内存测试数据库，不调用真实账号或付费模型。

接口与兼容性：提供 `prepare_sample_input()`、`run_sample_analysis()` 和 `analyze_sample_sources()` 内部服务入口，没有新增外部 API。结果可放入现有阶段状态后序列化，但未接入任务数据库检查点、质量评委、质量返工或前端。`not_reviewed` 显式说明结果尚未经过质量评审，引用真实并不意味着结论正确。

可留作简历的技术事实：拆分具有独立输入/输出协议的分析角色，实施多样本覆盖与原文证据校验、输入预算和有限修复；不得据此宣称内容可用率、成本或流量已提升。

自动化验证：后端全量 283 项通过（本轮新增 47 项，1 条 warning）；前端生产构建通过，仍有既有主 bundle 体积提示。测试覆盖 3/20/30/50 篇、输入白名单、缺失数据、来源/引文错误、一次修复、畸形 JSON、取消回调、模型归属和传输异常不重发。仅验证结构与程序行为，没有验证真实模型的归纳质量或抗提示词攻击效果。

Git 状态：代码提交 `52e9605`（`功能：实现 M3 样本分析 Agent 与来源校验`），已推送至 `origin/feat/ai-fashion-daily-report`；本节回填实际验证和推送记录。

### 5.6 M4 读者需求 Agent（独立模块）

问题背景：目标受众默认文字包含电商、服装、AI、时尚、营销、美工和后期从业者，直接交给综合提示词容易变成“所有人都适用”的空泛文案。M4 将受众词整理为具体工作场景和内容价值，为后续选题提供主要读者边界。

技术实现：

- 扩展 `backend/app/schemas/creative_agents.py`：新增 `AudienceBrief`、`AudienceSegment`、`AudienceNeed`、内容形式建议和带依据的 `AudienceEvidence`。
- 新增 `backend/app/services/creative_agents/reader_needs.py`：保留用户原始受众词，允许相关词合并但禁止遗漏或添加；把依据区分为 `sample_evidence`、`user_requirement` 和 `hypothesis`。
- 受众输入只包含关键词、受众、创作要求和已通过 M3 的分析产物，不发送 Cookie、API Key、原始正文、作者信息或媒体地址。
- 程序校验全部受众词覆盖、分组 ID、需求/形式引用、样本 note_id 归属和证据类型；质量问题最多一次修复，网络/HTTP/读取超时不自动重发。
- 新增 `tests/backend/test_creative_reader_needs.py`，覆盖受众拆分、输入白名单、样本注入隔离、受众覆盖、引用错误、有限修复、模型归属和三分钟读取超时。

接口与兼容性：提供 `prepare_audience_input()`、`run_reader_needs()` 和 `analyze_reader_needs()` 内部服务入口，没有新增外部 API；结果尚未写入 Task 阶段状态、质量评委或前端。`hypothesis` 只表示待验证推测，不能写入最终文案作为事实。

自动化验证：后端全量 301 项通过（本轮新增 18 项，1 条 warning）；前端生产构建通过，仍有既有主 bundle 体积提示。未调用真实小红书或付费模型，未验证受众判断的市场真实性或文案质量。

Git 状态：代码提交 `335d83a`（`feat: 新增读者需求 Agent`），已推送至 `origin/feat/ai-fashion-daily-report`；文档回填提交另行记录。

### 5.7 M5 选题 Agent（独立模块）

问题背景：直接生成标题容易先做夸张承诺，再让正文硬凑内容。M5 先把样本结论与主要读者对齐，明确这一篇写什么、提供什么价值、哪些信息必须覆盖和哪些效果不能承诺，为后续标题、文案与评审建立结构化依据。

技术实现：

- 扩展 `backend/app/schemas/creative_agents.py`：新增 `TopicBrief`、`TopicIdea`、`TopicEvidence`，分离主要读者、内容类型、核心切入点、读者承诺、正文要点、来源、事实边界和差异化说明。
- 新增 `backend/app/services/creative_agents/topic_selection.py`：复用结构化调度器，按用户选择生成 1/3/5 个选题；数量必须为整数，不接受布尔值或浮点数混入。传输选项显式设置数量时，必须与本阶段数量一致。
- 输入只使用用户关键词、要求和 M3/M4 简报，不重复发送原始完整正文、Cookie 或模型密钥。模型实例也重新做结构校验，并检查 M3 模式引用、M4 受众覆盖及跨阶段来源/分组引用。
- 输出校验唯一 idea ID、去除空白后的完全重复主题、有效主要读者和至少两个不同的样本来源；声明来源与依据来源的去重合集必须一致，单条引用列表不得重复。程序计算参考篇数，不把重复引用算成多篇。
- 将依据区分为 `sample_pattern`、`sample_observation` 和 `user_requirement`；用户要求不伪装成样本证据。JSON、结构或引用错误最多修复一次，网络/HTTP/读取超时不自动重发；保留模型归属检查及连接 10 秒/读取 180 秒超时。
- 新增 `tests/backend/test_creative_topic_selection.py`，包含 63 项模拟用例，覆盖数量和类型、输入不变性、上游引用校验、实例重新验证、去重/来源一致性、有限修复与耗尽、取消回调、跨用户拒绝、超时及安全错误信息。

接口与兼容性：提供 `prepare_topic_input()`、`run_topic_selection()` 和 `analyze_topics()` 内部服务入口；没有新增 API、页面、数据库阶段保存或自动调用，也没有替换旧生成流程。结果保留 `quality_review_status=not_reviewed`，未经过实际评委。

校验边界：本阶段不持有原始全文，不重新验证上游引句真实性；来源 ID 存在不证明依据陈述在语义上成立，完全重复检查也不能判断同义选题。原用户受众、批次及产物版本绑定由后续管线负责，语义、差异性和可用度需后续评委与人工验收，不宣称内容质量或流量已提升。

可留作简历的技术事实：实现跨阶段结构化创作简报，采用主要受众绑定、来源集合一致性和有限修复机制约束模型输出，结合模拟传输测试验证权限与超时边界；不将尚未接入的完整多 Agent 流程写成已上线成果。

### 5.8 M6 选题评委 Agent（独立模块）

问题背景：M5 的结构和来源 ID 校验不能判断一个选题是否具体、有价值或受到样本支持。M6 将生产与评价分离，让评委给出分项判断和定位明确的反馈，再由程序计算通过结果，避免模型自行修改规则或用一句“还不够爆款”要求无目的返工。

技术实现：

- 扩展 `backend/app/schemas/creative_agents.py`：新增 `TopicCriterionScore`、`TopicReviewIssue`、`TopicJudgement`、`TopicReviewResponse`；评委只交付分数、依据、问题和修改要求，模型输出不得夹带总分、通过标记或重写的选题。
- 新增 `backend/app/services/creative_agents/topic_review.py`：校验全部选题覆盖、五项评分唯一性、来源/关联选题 ID、问题字段与逐字引句；低于分项参考线必须有对应修改意见，阻断项低分必须明确标为阻断。
- 复用既定 `TOPIC_RUBRIC`：读者价值 30%、具体程度 25%、匹配度 20%、差异化 15%、样本依据 10%。加权总分保留两位小数，至少 6.5；前三个阻断项各至少 6 分，并且不能存在显式阻断问题。仅将原有 6.5 提取为共享常量 `REVIEW_PASS_THRESHOLD`，未调整评分权重或门槛。
- 上游 M3～M5 产物重新执行结构及引用校验；以正整数 `topic_revision` 和 SHA-256 输入指纹绑定用户要求、上游内容、选题和评分规则。模型不得返回其他版本的评审，字典键顺序不影响指纹。
- 程序生成 `TopicReviewResult`：保留所有选题的评审、通过名单和待修改名单，按原选题顺序输出；不静默删除低分选题，不减少用户要求的 1/3/5 个数量。未全部通过时返回 `revision_required` 与 `downstream_ready=false`。
- 有效的低分或显式阻断结果是正常完成的评审，不自动重评或改稿；JSON、结构、引用和反馈一致性错误仍最多修复一次。网络/HTTP/读取超时不重发，模型归属和三分钟读取超时沿用现有传输层。
- 新增 `tests/backend/test_creative_topic_review.py`：84 项离线用例，覆盖数量、指纹/版本、上游输入、规则计算、阻断优先、通过/待修改名单、反馈定位、伪造评分字段、非法数值、有限修复、取消、跨用户权限和安全传输错误。

接口与兼容性：提供 `prepare_topic_review_input()`、`run_topic_review()` 和 `analyze_topic_review()` 内部入口；模型评语与程序判定分开保存，结果可序列化。评委归属既有 `topic` 阶段，不修改 `PIPELINE_STAGE_ORDER`；未增加 API、页面、任务数据库写入、报告结构或自动选题返工。M5 仍可独立运行且返回未评审状态，M6 尚未自动串入旧流程；原计划 M13 的质量返工仍待实现。

校验边界：指纹只用于内容绑定，不是签名或权限凭证；后续管线仍需核对任务归属、当前版本和缓存失效。逐字引句只核对待评审选题中的位置，不重新核实原始全文或图片；模型评分和理由仍可能有偏差，需要人工校准，不能据此宣称真实文案可用率或流量提升。

可留作简历的技术事实：实现生产与评审职责隔离、程序控制的评分判定、产物版本/内容指纹绑定、逐项可追溯反馈，以及“格式修复”和“质量不通过”分离的调用控制；完整管线和真实质量收益尚未验收。

自动化验证：选题生成、选题评委和基础调度器定向回归 156 项通过；后端全量 448 项通过（本轮新增 84 项，1 条 warning），前端生产构建通过，仍有既有主 bundle 体积提示。测试全部使用模拟模型和隔离数据库，没有调用真实小红书或付费模型，没有修改本地配置或重启服务。

## 6. 质量问题与后续优化

最近真实结果的问题不是 JSON 格式，而是内容策略：标题容易停留在“颜色/氛围/设计描述”，正文容易变成作品说明，缺少明确读者收益。下一阶段不继续堆长提示词，而是分阶段生成并评审：

1. 先让样本分析 Agent 提炼高频选题、开头结构、内容价值和受众痛点。
2. 让选题 Agent 先写清楚“读者为什么要看”和“这篇提供什么”。
3. 标题 Agent 按既定候选数量生成标题，由评委比较并选优；最终仍保持用户选择的 1/3/5 个标题，不改成固定数量。
4. 文案 Agent 只负责围绕已通过的标题写可直接发布正文。
5. 配图 Agent 不再干扰正文写作，只处理画面方案和提示词。
6. 最终评委检查标题、正文、标签和配图是否成套。
