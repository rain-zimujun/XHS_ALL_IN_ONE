# 工作台联动梳理：热点创作 ↔ 草稿工坊 ↔ 发布中心

> 目的：把「热点创作」产出的成稿、配图、发布串成一条闭环，并盘点其他功能可以怎么接。
> 状态：调研完成，方案待确认。

## 1. 现状盘点

导航里「高级功能」分组下的页面，后端能力其实都是完整的，不是占位。

| 功能 | 数据落在哪 | 已具备的能力 | 与热点创作的关系 |
|---|---|---|---|
| **草稿工坊** | `ai_drafts`（标题/正文/标签）+ `draft_assets`（图片/视频，可排序） | 新建/编辑/删除、素材上传与排序、素材优化、AI 描述、**转发布任务** | 成稿的天然承接处，但**缺入口** |
| **发布中心** | `publish_jobs` + `publish_assets` | 立即/定时发布、素材上传、Creator 接口发布、失败重试、取消 | 草稿的下一步，需 **Creator 账号** |
| **图片工坊** | `ai_generated_assets` / `files` | 上传、裁剪、合成（封面文字）、**AI 生图**（OpenAI 兼容 `/images/generations`，支持参考图） | 配图方案 → 真实图片，但**缺调用入口** |
| **内容库** | `notes` | 已保存笔记、筛选、批量加入草稿、批量打标、导出 Excel | 素材回流，已通草稿 |
| **笔记发现 / 数据抓取** | `notes` | 关键词/URL/用户笔记、评论采集 | 可扩充热点创作的样本来源 |
| **数据洞察** | 聚合查询 | 总览、爆款内容、热门话题、互动、关键词趋势、评论洞察、竞品榜 | 反哺选题与关键词 |
| **竞品监控** | `monitoring` | 监控目标、快照、竞品笔记、**一键生成草稿** | 竞品 → 草稿，已通 |
| **关键词组** | `keyword_groups` | 关键词分组管理 | 可做热点创作的搜索预设 |
| **自动运营** | `auto_tasks` | 关键词 + PC 账号 + Creator 账号 + 定时 → 搜索、改写、草稿、发布（简化旧流程） | 未来可换成新链路 |
| **任务中心** | `tasks` | 异步任务查询、取消、重试、调度状态 | 全链路任务可见 |
| **通知** | `notifications` | 任务完成/失败提醒 | 长任务提醒 |

### 已经被验证的衔接模式

仓库里已经有两条「别的模块 → 草稿」通道，说明 `AiDraft` 就是设计上的通用承接口：

- `POST /api/notes/batch-create-drafts`：内容库勾选笔记 → 批量建草稿；
- `POST /api/platforms/xhs/analytics/benchmarks/{id}/create-drafts`：竞品监控 → 建草稿。

**唯一缺的，就是热点创作 → 草稿这一条。**

## 2. 两个硬约束（决定方案可行性）

### 约束一：发布需要 Creator 账号

```python
if account.platform != "xhs" or account.sub_type != "creator":
    raise HTTPException(400, "Creator account required")
```

搜索、采集用的是 **PC 账号**；发布走的是 **Creator（创作服务平台）账号**，是两种登录、两套 Cookie。也就是说：

- 想让「草稿 → 发布中心 → 一键发」，必须额外绑定 Creator 账号；
- 发布前素材还要先上传到小红书（`publish_assets.upload_status`），不是本地路径直接发。

### 约束二：生图要单独的图片模型

`/api/ai/images/generate` 要求用户有一个 `model_type="image"` 且 `is_default=True` 的模型配置，调用的是 OpenAI 兼容的 `/images/generations`，支持单图或多图参考（image-to-image），返回 URL 或 base64。

**这一点是好消息**：热点创作已经产出了结构化、可直接使用的生图提示词（构图/镜头/光线/配色 + 末尾「画面中不要出现…」），只要把它接到这个接口上，配图就能在本工具内直接生成。

## 3. 建议的闭环

```
热点创作（LangGraph 生成）
   ↓ 勾选想要的版本
【新】一键存入草稿工坊（每版一条草稿 + 标签 + 配图）
   ↓ 可选：一键生成配图（用 image_plan.prompt 调生图模型）
草稿工坊（改文案、换图、排序、优化素材）
   ↓ 已有能力：send-to-publish
发布中心（选 Creator 账号、立即或定时）
   ↓ 已有能力：上传素材 + Creator 发布
已发布（记录 external_note_id）
   ↓ 可选：数据洞察跟踪表现 / 竞品对比
下一轮选题
```

## 4. 分阶段实现

| 阶段 | 内容 | 涉及改动 | 预估 |
|---|---|---|---|
| **P0** | 创作结果 → 草稿工坊 | 新接口 `POST /creative/runs/{id}/save-to-drafts`；草稿加来源字段（task_id / variant_id）做幂等；结果区加「存入草稿工坊」按钮（单版 + 全部） | 0.5～1 天 |
| **P0** | 草稿 → 发布更顺手 | 草稿页把「选择 Creator 账号」做成必填且显眼；没有 Creator 账号时引导去绑定 | 0.5 天 |
| **P1** | 配图方案 → 内置生图 | 新接口 `POST /creative/runs/{id}/generate-images`（按 variant 批量、并发限流、逐张记失败）；结果区显示「将生成 N 张，约 N 次调用」；生成的图直接成为草稿素材 | 1～2 天 |
| **P1** | 自动运营接新链路 | 把 `auto_tasks` 的简化流程换成「跑一次热点创作 → 存草稿 → 定时发布」 | 1～2 天 |
| **P2** | 数据反哺 | 发布后把 `external_note_id` 拉回互动数据；关键词趋势 → 搜索预设 | 1 天 |
| **P2** | 竞品监控接热点创作 | 竞品笔记直接作为热点创作样本（比现在的「生成草稿」更完整） | 1 天 |

## 5. 需要你先定的几个产品问题

1. **存草稿的粒度**：一个标题存一条草稿（含 3 版正文），还是每个版本各存一条？
   - 建议：**每版一条**，标题带版本名（如「标题 A · 版本 2」），方便单独发布和 A/B。
2. **配图生成范围**：默认只生成封面图，还是把每版的所有配图都生成？
   - 建议：默认生成**每版第 1 张（封面）**，其余让用户按需勾选，避免一次烧掉几十次调用。
3. **是否把草稿工坊 / 发布中心提到主流程**：现在它们挂在「高级功能」下，如果这条闭环成立，建议移到「搜索·创作·报告」分组，和热点创作平级。
4. **发布账号**：你是否已经有 Creator 账号可绑？没有的话，P0 的发布环节只能到「草稿」为止。

## 6. 风险

- **生图成本不可控**：一次 5×3 全部生成可能几十张图，必须先给数量与费用提示；
- **发布失败原因复杂**：Creator 接口对图片尺寸、标题长度、敏感词都有要求，发布中心已有失败重试，但需要把常见原因翻译成人话；
- **合规**：自动生成 + 自动发布意味着无人复核，建议保留「发布前必须人工点一次」的硬约束，不做全自动。
