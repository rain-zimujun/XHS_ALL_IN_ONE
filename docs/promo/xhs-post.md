## 二、正文（可直接复制）

```
做了个小红书运营工作台，已经开源到 GitHub 了 🧵

起因很简单：每次写笔记，找参考、拆结构、写标题正文、想配图，一套下来两三个小时。干脆把它做成一条流水线。

现在它能做到这几件事：

① 两种找样本的方式
关键词搜一批，或者直接输昵称拉某个博主最近 300 篇（按最新或点赞排），勾选之后才去采集正文。

② 一条 13 个节点的生成链路
样本分析 → 读者需求 → 选题 → 标题 → 正文 → 配图 → 终审。
每个阶段单独写、单独评，不是一个请求糊出全部内容。

③ 评委打分 + 定向返工
标题、正文、终审都有评分（0～10，6.5 分算过）。
没过就只改有问题的对象和字段；已经通过、文本没变的部分会被"冻结"，不再重复送审。

④ 长任务能暂停、能接续
跑到一半停下来，之后点继续，已完成的批次直接复用，不用从头再来。
模型超时、网络抖动也会自动重试，实在不行还能从失败阶段接着跑。

⑤ 配图提示词能直接拿去用
数量可以自己配（比如 5～9 张），会写清构图、镜头、光线、配色、材质，最后统一加一句"画面中不要出现……"，复制到文生图平台就能出图。

技术上是 Python + FastAPI + LangGraph，前端 React 19 + Ant Design，数据库用 SQLite 不用装。整个跑在本地，数据也在本地。

⚠️ 说清楚几点：
· 个人项目，只用于学习和自己练手
· 需要自己配一个 OpenAI 兼容的模型接口
· 生成内容必须人工核实后再发，别直接拿去商用或刷量
· 模型分只是参考，不是流量保证

仓库：github.com/rain-zimujun/XHS_ALL_IN_ONE
（GitHub 直接搜 XHS_ALL_IN_ONE 也能找到，README 里有快速启动）

有问题、或者想要什么功能，评论区说，我尽量加 🙌
```

## 五、发布建议

1. **链接处理**：小红书正文里的链接不可点击，且带外链可能被限流。建议正文放一次「仓库：github.com/…」，**同时在第一条评论再发一遍完整链接**。
2. **发布时间**：工作日 12:00–13:00 或 20:00–22:00；技术类内容周末晚上也不错。
3. **封面**：用 `01-cover.png`；如果测试发现点击率低，可以换 `03-pipeline.png`（成稿截图更直观）做 A/B。
4. **首评置顶**：第一条评论写「README 里有完整的功能说明和快速启动，跑不起来可以在这条下面问」。
5. **不要写的表述**（容易违规或招黑）：保证爆款、涨粉、提效 X 倍、一键搬运、免审核。
6. **被问到"能不能直接用"时**：如实说需要自己配模型 API、要扫码登录自己的账号、内容仍要人工过一遍。
