# 热点创作：手动流程使用与验收

默认使用个人 Fork `rain-zimujun/XHS_ALL_IN_ONE` 的 `master` 分支，后续更新直接交付该主分支。本阶段完成手动搜索、选取、正文采集、AI 策划和报告导出。定时日报、自选输出目录、Excel、桌面安装包还未实现。

## 使用步骤

1. 启动后端与前端，登录本工具的平台账号。这与小红书账号是两套登录。
2. 在“账号绑定”绑定自己的小红书 **PC 账号**。出现登录失效或验证码时，由你手动完成验证；本工具不会绕过验证。
3. 在“模型配置”添加文字模型，填写服务地址、模型名称和 API Key。
4. 打开左侧“热点创作”，输入关键词，例如“AI 服装设计”“AI 模特”“虚拟试衣”。选择排序、发布时间、笔记类型，以及目标 20/30/50 篇。
5. 搜索后勾选样本。数量是目标上限；平台返回不足时据实提示。结果保留平台排序，不把点赞数当作严格的全站热度。
6. 设置目标受众、创作要求、1/3/5 个标题及每个标题 2/3 版文案（默认 3 个标题 × 3 版）。点击“采集并生成”。至少选择 3 篇不同笔记，至少成功获得 3 篇正文才会分析。也可先“仅采集”，以后再用已有正文生成。版本越多通常耗时和费用越高，首次可选 1 个标题 × 2 版。
7. 任务在后端继续运行，刷新页面后在“历史任务”打开。支持停止；已发出的抓取/模型请求不能撤回，停止会阻止后续处理。
8. 在结果区先点击标题，再选择下方的“文案 1 / 2 / 3”。正文、标签、封面文字、配图建议、正向/负向生图提示词按版本成套切换，不会再次调用模型。“复制正文和话题”复制可直接发布的正文及 `#话题`；“复制完整笔记”复制当前标题、当前正文和话题，不混入界面说明、推荐理由或提示词。自行审稿、配图和发布。
9. 新任务默认按样本、受众、选题、标题、正文、配图和终审逐阶段创作；任务区显示状态、版本与质量返工。结果可按标题/正文/终审评分排序和筛选；正文/终审排序及筛选使用标题下最高分版本，当前正文徽章仍显示当前版本分数。标题、正文评审和总评审/返工记录均默认收起，失败任务也能查看已经保存的阶段记录。

多 Agent 首次全部通过通常有 10 次模型请求；每个生产阶段最多质量返工 2 次，总计最多 36 次请求，任务开始 30 分钟后不再开始新请求。格式修复同样计入请求预算；各次请求仍使用连接 10 秒/读取 180 秒的限制。高级生成选项中可切换旧版流程进行对照，已有无流程标记的任务保持原有行为。模型评分不是流量或可用度保证。

## LangGraph 试用（2026-10-22）

在“AI 创作设置 → 高级生成选项 → 生成方式”选择 **LangGraph 分阶段创作与评审（试用）**。可以先打开已有采集任务，选 1 个标题 × 2 版文案，再点击“使用已采集正文重新生成”；会新建模型分析任务，不重新采集，不改写原任务。

LangGraph 版使用集中状态和评审条件边，仍按样本、受众、选题、标题、文案、配图和终审展示进度。每个角色绑定独立 TypedDict 的原生 JSON Schema，程序管理版本和输入指纹；终审不通过时交回责任阶段并更新受影响内容。模型/接口仍需支持严格 JSON Schema。

默认生成方式仍保留此前多 Agent 版，试用需要手动选择；刷新后打开 LangGraph 历史任务会恢复该任务的生成方式。三种方式可切换，查看历史或切换选项本身不会调用模型。新图的请求预算、超时和质量门槛与此前一致，不能据此保证成稿质量。开发结构与当前边界见 [LangGraph 实现说明](langgraph-workflow.md)。

任务数据库逐次保存 `payload.graph_state` 全局状态及兼容的 `payload.pipeline` 阶段快照；失败时可区分 JSON/字段错误、来源/ID 关联错误、评审返工耗尽和网络超时。HTML/JSON 报告沿用版本 3 的结果和评审结构；完整快照支持用户主动从模型失败阶段接续，仍不支持重启后自动续跑。

## 文案风格与结果分块

- 新任务默认目标受众为“电商、服装行业、AI、时尚行业、营销行业、美工、后期从业者”，默认创作要求为“符合小红书爆款文案的调性，文案尽可能精简、抓眼球”。两项均可编辑；历史任务恢复原有设置，不用新默认值覆盖。
- 生成规则要求先归纳本批所有成功采集正文的共同风格：开头、语气、段落和句子长度、表情、话题、互动结尾，再据此写成可发布的原创正文。不同版本采用不同开头、叙述角度或组织方式，但都围绕对应标题。
- 默认写给读者看的作品／灵感分享成稿，不因关键词含 AI 或受众是从业者就写成设计指导、提示词教程。只有在创作要求中明确提出教程、步骤或教学时才写教程。正文不夹带给发布者的制作指令、编辑备注、占位符、配图说明或免责声明；相关建议和核查提醒保留在正文之外。
- 标签独立存放；模型把标签重复写到正文末尾时，程序只将末尾独立话题行移到标签栏并去重，不删改正文句子、表情和正常编号。历史任务查看与重新导出也采用相同规则，不改写数据库中的旧结果。旧下载文件要重新导出才会更新格式。
- 新生成正文中的明确编辑字段标记（例如“配图建议：”）、助手开场白及待填占位符会触发校验，在原有最多一次修复机会内要求模型重写。规则不能识别所有生硬措辞；是否自然、是否真正适合直接发布仍需人工审阅，历史正文不会被自动重写。
- 不只参考标题或套用固定营销模板，不逐句改写原文，不假冒作者、不编造亲测经历。风格来自本批有效样本，不代表全站偏好，也不保证流量。实际文案质量仍取决于模型和样本，需要人工审阅。
- 每个标题有 2～3 版真实生成的正文；每版都必须有独立的配图方案和提示词。数量、必要字段、重复正文/版本名和引用会校验；语义质量及配图是否充分对应仍需人工核对。
- “推荐理由与参考来源”“样本分析与文案风格依据”默认折叠，需要时展开。
- 旧历史结果保持正文措辞不变，仅做末尾话题分离，用新界面显示原有的 1 版，不伪造额外选择。若要多个版本或调整文案口吻，点击“使用已采集正文重新生成”；会调用文字模型，但不重新采集，旧任务仍保留。仅刷新、切换或重新导出不会调用模型。

## 精简界面与高级功能

- 登录后默认进入“热点创作”，主导航只突出“热点创作、账号绑定、模型配置”。
- 原来的总览、发现、抓取、内容库、图片/视频工坊、发布、自动运营、任务中心、设置和平台选择都保留在默认收起的“高级功能”菜单中。展开即可使用，原页面地址仍有效；直接打开高级页面时会展开对应菜单。
- 模型配置页默认只展示文本模型，展开“高级模型功能”后才显示图片模型与服务参考。
- 绑定账号默认 PC 扫码；Creator、验证码、手动 Cookie 和同步 Creator 等选项放在“高级登录选项”中，不删除原有能力。
- 这里只调整入口显隐，不删除账号、模型、任务、数据或接口，也不自动运行高级功能。

## 报告文件

- 自动写入 `backend/app/storage/exports/`，页面显示该目录的绝对路径。
- 名称为 `xhs-report-u用户ID-时间-t任务ID.html/json`。不同任务不会覆盖彼此。
- HTML 是可直接打开的阅读版，按标题及其各文案版本分块，包含所有版本，不仅是页面当前选中的版本；JSON 包含方案、搜索/创作条件、失败记录和完整采集正文。多 Agent 报告 `schema_version=3`，额外保存 `pipeline` 的阶段状态、产物、评审及返工历史，文案及配图仍在 `result.ideas[].variants[]`。旧流程多版本/单正文分别保留版本号 2/1，不补造评分或额外文案。
- 多 Agent 阅读版展示标题、正文和终审评分；分项理由、具体问题及返工记录默认折叠，独立于发布正文。阶段概览显示实际请求计数与质量返工；历史/失效评审仅供追溯，不代表当前通过。重新导出不调用模型；旧下载文件需重新导出才有新版展示。
- 页面下载需要本工具账号登录，不同用户不能下载彼此报告。HTML 文本安全转义，不加载原图或执行生成脚本。
- 写文件失败不会丢失已生成方案，可点击“重新导出报告”。目录、数据库和生成文件不应提交到 Git。

## 失败处理与当前边界

- 2026-10-22 起，后台终端输出以“创作诊断”为标记的中文事件，包含任务编号、生成方式、阶段/Agent、尝试次数、耗时、错误类型、原因和是否继续修复；评审结束单独记录通过/待修改状态。LangGraph 和此前多 Agent 版均覆盖，旧综合生成记录任务开始/结束及受控失败原因。
- 阶段进度下新增默认折叠的“失败详情”，可展开查看并复制各次已保存的校验错误及耗时。结构错误定位到字段与数组下标；样本引用不匹配还显示输入样本序号（从 1 开始）、引用字段和摘录字数，JSON 数组下标从 0 开始。历史任务只能显示当时保存的信息，不能补回过去没有记录的细节。
- 诊断不会输出 API Key、Cookie、请求头、完整提示词或完整模型响应；引用错误只记录位置和规则，不打印原文或模型引句。网络/HTTP 错误使用受控提示，未知异常只记录类型。终端输出本身不额外写入日志文件，阶段失败摘要仍随任务快照持久化。内容校验门槛不变，网络重试与接续规则见下文。
- 创作请求会通过 `response_format.type=json_schema` 和 `strict=true` 向模型服务传递完整输出结构，覆盖生产、评审、修复和旧版综合生成；使用的模型及中转接口需要支持 JSON Schema 结构化输出，仅连通测试成功不代表支持此能力。服务拒绝参数时显示相应 HTTP 错误，不自动改成普通文本重新计费。格式约束不代替来源真实性或文案质量校验，也不能解决 HTTP 504/524 网关超时。
- 部分笔记失败：保留成功正文及失败条目；登录/验证码异常时停止采集并提示重新验证。
- 模型失败：保留正文，调整模型或要求后点击“使用已采集正文重新生成”。不会再次抓取。
- 创作分析使用连接超时 10 秒、读取超时 **180 秒（3 分钟）**；只影响本流程，不改变模型连通检查及其他短文本功能。连接失败、读取超时、HTTP 错误和响应解析失败分别提示。读取超时是等待响应数据的限制，不是整个采集/分析流程的总时长。
- 多 Agent 和 LangGraph 的临时模型服务故障自动额外重试 5 次（首次加重试最多 6 次），通常间隔 15、30、60、90、120 秒；服务端 Retry-After 优先，超过 300 秒时停止自动重试。每次请求仍是 10/180 秒超时，网络重试和格式修复分开计数，均受总预算约束。400/401/403、参数不支持、正文/来源/Schema 校验错误不会按网络故障重试。旧综合生成保留原来的不自动重试网络请求策略。
- 超时原请求仍可能在中转完成并计费；启用网络重试可能增加费用。进度展示当前等待与重试次数，“失败详情”保存各次网络失败及耗时；刷新不会额外发起模型请求。
- LangGraph 模型服务失败后若显示“从失败阶段继续”，点击后创建关联新任务，保留原素材、设置、已完成稿件和评审，从失败的具体 Agent 继续；不重新搜索、采集或生成前面的内容。比如标题生成成功、标题评审超时，仅重试标题评审。接续仍计入同一链路的 36 次请求上限，新任务重新开始 30 分钟执行窗口；原任务保留，重复点击不会创建多个并行子任务。若接续任务再次失败，从最新任务继续。
- 接续按钮仅适用于有完整快照的 LangGraph 模型连接、读取、HTTP、响应解析错误，以及请求未用尽的执行窗口超时。本次标签 Schema 从恰好 6 个调整为 5～8 个，历史失败详情若明确记录旧版标签校验错误，也会临时显示接续入口；其他结构、来源、业务、质量失败不会开放。接续会从失败的 Agent 重新生成并执行当前校验，不会跳过校验；不适用于素材/质量失败、取消、重启中断或请求预算耗尽。接续使用原模型配置 ID；可先修正原模型配置，再点击接续。修改素材或创作要求、旧综合生成与多 Agent 版仍使用“使用已采集正文重新生成”。接口说明见 [LangGraph 实现说明](langgraph-workflow.md)。
- 搜索未返回发布时间时显示“待采集补全”；正文详情返回后自动回填，历史采集任务同样能查看。搜索历史也会读取自己已保存的详情时间，不需要重新抓取，不修改原搜索快照。确实缺失的时间不会猜测或伪造。
- 模型格式或来源不合格：最多重试一次；每套至少引用两个不同且存在于样本中的笔记。结构校验不等于事实核查，发布前仍需人工审阅。
- 为控制输入体积，所有有效样本都会参与，但每篇最多使用 `min(1800, 24000 / 样本数)` 个字符。短文原样使用；长文在此预算内保留开头约 2/3、结尾约 1/3，并标记中段省略，以保留开头、互动结尾和话题风格。实际截取方式和上限显示在结果中。旧任务仍标记原先的开头截取方式，报告保留完整正文。没有分析原图、评论内容或视频画面。
- 生成会把样本文字交给你配置的模型服务，可能产生费用；遵守该服务的数据处理规则。不会自动调用生图或发布接口。
- 当前后台任务使用单进程内任务，后端必须保持运行。重启会把中断任务标为失败并保留已保存数据，尚不支持断点续爬或分布式多 worker。
- 原项目的“自动运营”“发布中心”等入口仍保留；新流程不调用它们。本地试用配置关闭了原项目后台定时器，不代表已经实现本需求的定时日报。
- 小红书实际搜索、筛选与账号状态受平台接口影响，离线测试不能替代真实账号验收。无法承诺内容一定获得流量。

## 开发验证

在项目根目录执行：

```bash
.venv/bin/python -m pytest tests/backend -q
node --test tests/frontend/creative_reviews.test.cjs
npm --prefix frontend run build
```

可选浏览器测试：需要已启动前端、Chrome 和 Playwright（可安装在独立测试环境，无需作为运行依赖）。执行 `node tests/browser/hot_content_smoke.cjs`；若 Playwright 不在项目依赖中，通过 `NODE_PATH` 指向其 `node_modules` 目录。

浏览器测试拦截全部 `/api/` 请求，覆盖 30 篇搜索/筛选、取消勾选、采集生成、3 个标题及每个文案版本与配图联动、完整复制、风格依据、报告下载、刷新恢复历史及参数回显、旧结果兼容和窄屏布局。默认测试 3 版，也可设置 `XHS_TEST_VARIANTS=2` 测试 2 版。后端测试使用临时数据库和模拟平台/模型，覆盖 20/30/50 篇全部有效样本参与风格提炼、首尾截取、格式及重复校验和新旧报告。没有使用你的真实账号抓取，没有调用付费模型，没有发布内容。

前端评审适配器单测使用 Node 自带 TypeScript 类型擦除，需要 Node 22.18+ 或 24；这不是程序运行时的新依赖。浏览器 smoke 支持 `XHS_TEST_BASE_URL` 指定热点创作地址、`XHS_TEST_ORIGIN` 指定导航测试服务地址，可使用单独测试端口而不中断现有服务。热点流程还覆盖评分排序/筛选、按版本关联评审、复制隔离、失败问题/责任阶段/返工历史，以及重复 React key 检查。

`tests/browser/focused_navigation_smoke.cjs` 另外验证三个核心导航、高级菜单展开/收起、侧栏折叠、登录默认入口、图片模型与账号选项折叠，以及原高级页面的直接访问。

`node tests/browser/creative_recovery_smoke.cjs` 验证网络故障详情、接续按钮、新任务轮询和窄屏。使用独立 Chrome、模拟全部 API，不读取用户浏览器会话、不实际采集或调用模型。

执行 `XHS_TEST_WORKFLOW=langgraph XHS_TEST_VARIANTS=2 node tests/browser/hot_content_smoke.cjs` 可验证 LangGraph 模式选择、请求参数和历史恢复；API 全部模拟，不消耗真实模型额度。

`node tests/browser/report_smoke.cjs` 不需要运行前后端服务：通过 `.venv/bin/python` 执行真实管线与报告渲染器，全部使用模拟模型响应，再用 Chrome 验证 3 标题 × 2 版报告评分、默认折叠、返工追溯、窄屏和零网络请求；可通过 `XHS_TEST_PYTHON` 指定测试 Python。该脚本同样需要可访问的 Playwright。
